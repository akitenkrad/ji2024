# CLI リファレンス

Rust バイナリは `srap` (`cargo build --release` で生成)．サブコマンド: `run`, `sweep`, `poa`, `reproduce`．

## 共通環境フラグ (`run`, `sweep`, `poa`)

| フラグ | 既定 | 意味 |
|--------|------|------|
| `--n-applicants` | 60 | 合成応募者数 |
| `--pool-ratio` | 0.5 | n_resources / n_applicants (希少性) |
| `--max-rounds` | 10 | ラウンド上限 (枯渇 / 全員退出で早期 stop) |
| `--visible-subset-size` | 5 | 可視資源サブセット V(p_j) のサイズ上限 |

> 合成環境パラメータ (応募者数・資源数・プロファイル分布) は論文本文に明示がない ([再現](reproduction.ja.md) 参照)．ここでは標準的な既定値で外部化する．

## `run` — 単一ポリシー

```bash
cargo run --release -- run \
    --entry-condition p_select --resource-subset r_size --queue-strategy fifo \
    --queues 3 --k 3 --c 2 --runs 10 --seed 42
```

| フラグ | 既定 | 値 / 意味 |
|--------|------|----------|
| `--entry-condition` | `p_select` | `p_budget` / `p_family` / `p_select` (E_queue) |
| `--resource-subset` | `r_size` | `r_size` / `r_rent` / `r_random` (R_queue) |
| `--queue-strategy` | `fifo` | `fifo` / `vfa` / `vfr` (S_queue) |
| `--queues` | 3 | m (キュー数) |
| `--k` | 3 | k-deferrals |
| `--c` | 2 | 選択キュー容量係数 |
| `--runs` | 1 | 独立試行数 (seed から派生) |
| `--seed` | random | コア RNG seed |
| `--temperature` | 0.0 | LLM 温度 |
| `--llm-seed` | 0 | LLM バックエンド seed |
| `--cache-path` | `.llm_cache/cache.json` | プロンプト→応答キャッシュ (`--mock` 時は無視) |
| `--output-dir` | `results` | 出力ベース |
| `--mock` | false | ライブ LLM の代わりに scripted mock (オフライン) |

**親 run 1 本** (条件と試行数の宣言) と **試行ごとの子 run** (`subcommand=run-replicate`) を `<output-dir>/srap-allocation/<run_slug>/` に記録する．ディレクトリ名は runvault が決めるので，タイムスタンプ付きディレクトリも `latest` シンボリックリンクも作らない．子 run はそれぞれ `metrics.csv` (ラウンドごとの `sw` / `avg_rsize` / `avg_wt` / `var_rsize` / `rop` / `co_gini` / `f_vnv` / `n_allocated` と，run スコープの `final_round`・`llm_calls` / `llm_cache_hits` / `llm_cache_hit_rate`)，条件 (`config.json` の `parameters`)，モデル・endpoint・温度 (`run.json` の `llm` ブロック) を持つ．

## `sweep` — ポリシー因子の感度分析

```bash
cargo run --release -- sweep \
    --entry-conditions p_budget,p_family,p_select \
    --resource-subsets r_size,r_rent,r_random \
    --queue-strategies fifo --runs 30 --seed 42
```

格子の定義を持つ **親 run 1 本** と，**試行ごとの子 run** (`subcommand=sweep-point`) を記録する．セル座標 (`entry_condition` / `resource_subset` / `sort_strategy`) は子 run の `parameters` に入るので，«セル列を持たないまま全セルの行を積んでいた» 旧 `metrics.csv` は無くなった — 同一セルの試行は `config_hash` が一致し，旧 `sweep_summary.csv` の列は `srap_tools.runs.sweep_table` が子 run から組み直す．

## `poa` — Policy Optimization Agent

```bash
cargo run --release -- poa --objective satisfaction \
    --iterations 50 --pool-size 50 --use-predictor --seed 42 --mock
```

| フラグ | 既定 | 意味 |
|--------|------|------|
| `--objective` | `satisfaction` | `satisfaction` / `fairness` (f(π) の重み) |
| `--iterations` | 20 | GA 世代数 M |
| `--pool-size` | 12 | 個体群サイズ |
| `--mutation-rate` | 0.2 | 遺伝子単位の突然変異率 |
| `--tournament-size` | 3 | トーナメントサイズ |
| `--use-predictor` | off | サロゲート `f̃` でフル評価を枝刈りする |
| `--mock` | off | scripted-mock 適応度 (オフライン)．外すと live-LLM 適応度 |
| `--cache-path` | `.llm_cache/cache.json` | 永続プロンプトキャッシュ (live 時; 世代間で共有) |
| `--seed` | 42 | RNG seed |

適応度 = 1 回の SRAP 配分実行を `f_pi(metrics, objective)` で評価する．run は 1 本で，世代パネルは `events.jsonl` の `x.ji2024.poa_generation` (`unit_id` = 目標，`t` = 世代，`t_unit` = `generation`; 最良/平均適応度・累積 `full_evals` / `evals_saved`・その世代の最良ポリシー)，最終解 π\* は `x.ji2024.poa_best_policy` (ポリシー・`final_fitness`・`improvement_pct`・`total_full_evals`・`total_evals_saved`)．世代パネルを `metrics.csv` に置かないのは，`reproduce` が同じ世代軸に 2 目標の系列を持ち `metrics.csv` に系列 ID の列が無いためで，両サブコマンドで形を 1 つに揃えてある．最良適応度は単調非減少 (エリート保存)．`--use-predictor` ではサロゲートが «現行エリートに勝てない» 評価をスキップする．

## `reproduce` — Table 2/3 + Fig.4

```bash
cargo run --release -- reproduce --mock --seed 42      # 高速スモークは --quick
```

| フラグ | 既定 | 意味 |
|--------|------|------|
| `--runs` | 10 | matched-seed 条件あたり試行数 (Table 2) |
| `--poa-iterations` | 20 | POA 世代数 (Table 3 / Fig.4) |
| `--poa-pool-size` | 16 | POA 個体群サイズ |
| `--mock` | off | scripted-mock 評価 (オフライン)．外すと live LLM |
| `--quick` | off | POA 予算・応募者数を縮小して高速化 |
| `--seed` | 42 | RNG seed |

Table 2 (matched-seed paired の社会的厚生順序; 論文の «r_size 最高 / r_random 最低» を paired win-rate で報告)・Table 3 (POA 最適化 `π_s*` / `π_f*`)・Figure 4 (POA 収束) を再現する．これはスイープではなく **run 1 本**である — paired 比較が条件をまたぐので，条件を子 run に割ると起きていない実行を主張することになる．Table 2 のセルは `events.jsonl` の `x.ji2024.table2_cell`，2 つの最適化は `x.ji2024.poa_generation` / `x.ji2024.poa_best_policy`，勝率は run スコープの指標 (`n_matched_environments`・`paired_wins_*`・`paired_win_rate_*`)，PASS / off-anchor の判定は `artifacts/reproduce_summary.json` に置く (判定とその帯は観測でも論文が印字した数でもない)．図は `uv run srap-tools reproduce` で生成する．
